# Живая игра: что нужно от бэкенда

Фронтенд говорит с бэкендом по WebSocket (JSON-сообщения). Адрес задаётся при сборке: `VITE_RELAY_URL=wss://…`. Референсная реализация: `server/relay.mjs` (Node, пакет `ws`). Если бэкенд пишется на другой платформе, нужно повторить этот протокол.

## Роли
- **Ведущий (host)**: создаёт комнату с секретным токеном, рассылает события всем.
- **Игрок (player)**: входит по коду, сообщает ведущему имя и ответы. Других игроков не видит.

## Сообщения клиент → сервер
| Сообщение | Кто | Смысл |
|---|---|---|
| `{t:"join", room:"AB3K", role:"host"\|"player", token?}` | все | вход; комнату создаёт только ведущий, токен хранится у него в `sessionStorage` и защищает от подмены |
| `{t:"emit", topic, data}` | только ведущий | отправить `data` всем в комнате как `{t:"msg", topic, data}` |
| `{t:"presence", patch}` | игрок | объединить `patch` со своим состоянием (`name`, `q`, `a`), и **отдать только ведущему** |

## Сообщения сервер → клиент
| Сообщение | Кому | Смысл |
|---|---|---|
| `{t:"joined", id, host}` | вошедшему | идентификатор соединения |
| `{t:"error", code}` | вошедшему | `no_room`, `not_host`, `full`, `not_permitted` |
| `{t:"msg", topic, data}` | всем | событие ведущего |
| `{t:"peers", peers:[{id,presence}]}` | ведущему при входе | кто уже в комнате |
| `{t:"peer", id, presence}` | **только ведущему** | игрок вошёл или изменил состояние |
| `{t:"left", id}` | только ведущему | игрок ушёл |

Важно для 200+ игроков: состояние игроков идёт только ведущему и по одному, иначе трафик растёт квадратично.

## Темы событий ведущего
- `st` {phase, code, i, total, endsIn, players, answered, right}
- `q` {i, title, text, options[4]}
- `h` {i, hint[], counts[4]}
- `sc` {i, part, parts, board, s:[[id6, score, gained, rank]…]} — по ≤100 игроков в сообщении
- каждое сообщение до 4 КиБ; ведущий повторяет текущее состояние раз в 1,5 с, поэтому опоздавший игрок видит экран сразу

## Нагрузка (проверено на `server/relay.mjs`, 200 ботов + ведущий)
- 200 игроков вошли за ~3 с, все ответы собраны за 10 с, ошибок 0.
- Игрок получает около 1–2 КБ каждые 1,5 с (≈ 1 КБ/с), ведущий получает по одному короткому сообщению на каждый ответ.
- Лимиты в референсе: до 400 игроков в комнате, 30 сообщений/с на клиента, сообщение до 16 КиБ.

Нагрузочный тест: `node server/loadtest.mjs ws://localhost:8787 КОД 200` (код берётся с экрана ведущего).

## Если бэкенд на Supabase Realtime
1. Канал `room:КОД`, события `broadcast` с теми же `topic` для ведущего → всем.
2. Ответы игроков **не** в общий `broadcast`, а в таблицу `answers(room, q, player, a, at)` или в `presence` с подпиской только у ведущего: иначе 200 игроков получат по 200 сообщений.
3. Следите за лимитами тарифа: число одновременных соединений и сообщений в секунду.
